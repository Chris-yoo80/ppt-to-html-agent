## 작업 1 보완: 물리·복합·업무 단위

앞선 마케팅 결과 표는 금액·수량·비율 모델의 검수 범위입니다. 이제 체크리스트에 길이·면적·부피·질량·시간·속도·에너지/전력·복합/업무 단위를 명시했습니다. [새 가상 단위 예제](../examples/unit-verification/README.ko.md), [자동 생성한 보고서](../examples/unit-verification/report.json)를 확인하세요.

`unit_audit.py`는 제공된 원본·표시 값, 차원, 정확한 환산 계수, 선택한 반올림 자릿수와 출처를 확인합니다. 새 가상 대조 14개 중 지원 환산 10개는 통과, 의도적으로 잘못되거나 정의가 없는 4개(m→m², 박스 기준 누락, 미지원 crate, 온도 오프셋)는 확인 필요입니다. 전체 보고서는 확인 필요입니다. 원본은 JSON이며 실제 엑셀로 검증한 것처럼 주장하지 않습니다.

추가 테스트는 역방향 길이 환산, 제곱·세제곱 계수, 에너지와 전력의 차이, 인원과 개수의 차이, 서로 다른 통화, 달력상의 월, 모호한 표현, 출처 누락, 잘못된 숫자, 업무 환산 정의, 임의로 입력한 거짓 통과까지 검사합니다. 선택 항목 unitChecks는 HTML 생성기가 다시 계산하며 근거 화면과 저장 HTML에 보존됩니다. 단위 대조값이 없으면 자동 검수 통과를 주장하지 않습니다.

한계: 등록된 환산만 지원하며 모든 단위를 자동 검증하지 않습니다. 박스당 수량·밀도·월의 길이·온도 오프셋·환율을 추정하지 않습니다. 캠페인 차트는 원화 기반이고 범용 물리량 차트에는 별도 변환 규칙이 필요합니다. 계산 통과는 원본 추출·정의·필터·분모 의미·화면 검증을 대신하지 않습니다.

## 작업 4: 처음 쓰는 사람용 빠른 시작

한·영 README 상단과 국문·영문 소개 페이지에 같은 3단계 흐름을 넣었습니다. 스킬 받기, Claude Code 또는 Codex의 프로젝트 스킬 폴더에 설치하기, 원본을 넣고 스킬을 요청한 뒤 목차와 대표 장면 확인하기 순서입니다. `docs/install.md`로 연결하며 Claude Code의 `/ppt-to-html` 요청과 Codex의 `$ppt-to-html` 요청을 구분했습니다.

자동 검사는 한·영 빠른 시작 문구, 로컬 링크, 영문 소개 페이지 생성과 패키지 일치를 확인합니다. 사용할 수 있는 브라우저 화면이 없어 시각 검토는 보류했습니다. push·병합·배포하지 않았습니다.
